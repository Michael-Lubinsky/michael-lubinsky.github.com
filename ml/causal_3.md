## Implementing causal inference algorithms from scratch is one of the best ways to learn the subject, especially if you already have experience with Python, SQL, and data engineering.

 I recommend a hybrid approach:

1. Implement the core algorithms yourself using NumPy and Pandas.
2. Test them on synthetic datasets with known causal effects.
3. Compare your results with established libraries such as `statsmodels`, `DoWhy`, and `Tigramite`.
4. Gradually introduce more sophisticated algorithms.

The most important thing to understand is that causal inference is not primarily about algorithms. It is about assumptions that allow causal effects to be identified from data.

A perfectly implemented regression algorithm can produce completely wrong causal conclusions.

## 1. Suggested learning roadmap

I would organize the project into six stages, using your store pricing dataset as a continuous example.

| Stage | Algorithm                                     | Implement from scratch?          | Difficulty |
| ----- | --------------------------------------------- | -------------------------------- | ---------- |
| 1     | OLS regression and confounding                | Yes                              | Easy       |
| 2     | Matching, propensity scores, IPW              | Yes                              | Moderate   |
| 3     | Difference-in-Differences (DiD)               | Yes                              | Moderate   |

I would not start with complex algorithms such as PCMCI, PC, FCI, or Double Machine Learning.

First understand the difference between an observational association and an intervention.

## 2. Start with a very simple causal experiment

Suppose product demand is generated by:

\\[ Q=100-5P+3U+\epsilon \\]

Where:

- \\(Q\\): number of purchases
- \\(P\\): product price
- \\(U\\): an unobserved demand factor
- \\(\epsilon\\): random noise

The true causal effect is:

\\[ \frac{\partial E[Q\mid do(P=p)]}{\partial p}=-5 \\]

Increasing the price by $1 causes five fewer expected purchases, assuming this structural equation describes the intervention.

Now suppose the store changes prices depending on demand:

\\[ P=10+0.5U+\eta \\]

This creates confounding because \\(U\\) affects both price and purchases.

### Implement the experiment

```
import numpy as nprng = np.random.default_rng(42)n = 10000# Unobserved demandU = rng.normal(0, 5, n)# Price depends on demandP = 10 + 0.5 * U + rng.normal(0, 1, n)# True causal effect of price = -5Q = 100 - 5 * P + 3 * U + rng.normal(0, 2, n)# Implement OLS manuallyX = np.column_stack([np.ones(n), P])beta = np.linalg.lstsq(X, Q, rcond=None)[0]print("True causal effect:", -5)print("OLS estimate:", beta[1])
```

The OLS coefficient will be biased because the unobserved demand factor influences both variables.

This is a fundamental causal inference lesson:

A statistical model can fit the observations well while giving an incorrect estimate of the effect of an intervention.

Try changing the relationship between \\(U\\) and \\(P\\). Observe how the estimated coefficient changes even though the true causal effect remains -5.

## 3. Learn causal graphs alongside the code

For example:

The backdoor path Price ← Demand → Purchases creates confounding. Demand is unobserved, so ordinary regression cannot adjust for it directly.

You should learn how to identify:

- Confounders
- Mediators
- Colliders
- Backdoor paths
- Interventions using the `do()` operator

These concepts explain when an algorithm's output can be interpreted causally.

## 4. Extend the experiment to time series

Once you understand the basic case, introduce time-dependent variables.

For example:

\\[ Q_t=100-5P_t+0.4Q\_{t-1}+3U_t+\epsilon_t \\]

\\[ P_t=10+0.02Q\_{t-1}+0.5U_t+\eta_t \\]

Now we have:

- Autocorrelation in purchases
- Feedback from past purchases to current prices
- Unobserved time-varying confounding
- A known structural effect of current price

This is much closer to your store dataset.

An interesting exercise is to compare four estimators:

1. Simple OLS: \\(Q_t\sim P_t\\)
2. Regression controlling for \\(Q\_{t-1}\\)
3. Regression controlling for \\(Q\_{t-1}\\) and \\(U_t\\) (possible only in simulation)
4. An estimator using randomized price interventions

Compare how accurately they recover the true coefficient of -5.

## 6. What not to implement from scratch

I would avoid spending time implementing generic numerical optimization, matrix decomposition, or advanced statistical distributions unless you specifically want to learn numerical methods.

Use NumPy for linear algebra, SciPy for optimization and distributions, and Pandas for data handling.

Implement the causal logic and estimators, not the low-level mathematical infrastructure.

For example, writing the backdoor adjustment estimator yourself is educational. Writing your own matrix inversion routine usually isn't.

##  suggested first project

I would begin with a synthetic store simulator with one product, implementing the following experiments:

- Random price changes → OLS should recover the true effect.
- Prices depend on customer demand → OLS becomes biased.
- Demand is observed → backdoor adjustment can recover the effect.
- Demand is hidden → explore what additional assumptions or experimental design would be needed.

Then add multiple products, lagged effects, and dynamic pricing.

Causal effect estimation and causal discovery are different subjects.   
Effect estimation asks how much changing a price affects sales.  
Causal discovery tries to determine which variables cause which others. 

I recommend learning effect estimation first, then causal discovery algorithms such as PC and PCMCI.

That sequence will teach you not only how causal algorithms work, 
but also why they sometimes fail.
